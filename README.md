# Музей несбывшихся планов

React + Vite + React Router (клиент), Express + SQLite (сервер). Данные в `data/museum-v3.db`.

## Запуск
    cp .env.example .env
    npm install
    npm run dev                                  # сайт :5173, API :3001
    npm run build && node --env-file=.env server/index.js   # продакшен на :3001
    docker compose up -d --build                 # или Docker

## Страницы
`/` главная, `/exhibition` экспозиция, `/idea/:id` идея, `/submit` сдать идею, `/halls` залы сходств, `/mix` сочетания, `/login`, `/register`, `/profile`.

## Аккаунты
Регистрация по имени, почте и паролю. Пароли хранятся как scrypt-хэш с солью, сессии лежат в SQLite (в куке только случайный токен, в базе его хэш; HttpOnly, SameSite=Lax, 30 дней). Читать могут все, писать, лайкать и обращаться к ИИ только вошедшие. Идею и продолжение можно публиковать анонимно, имя сохраняется в базе, но не показывается. Три жалобы от разных аккаунтов скрывают идею.

### Назначение модератора

Владение почтой при регистрации не проверяется, поэтому `ADMIN_EMAIL` больше не выдаёт права. По умолчанию модераторов нет; существующие аккаунты и схема базы сохраняются. Оператор сервера должен самостоятельно проверить личность и владение уже созданным аккаунтом.

1. Владелец входит по защищённому соединению и открывает `/api/auth/me`; поле `user.id` содержит ID аккаунта. Оператор независимо подтверждает, что ID принадлежит нужному человеку, или проверяет его через доверенный административный доступ к базе.
2. Оператор указывает проверенные существующие ID в защищённой конфигурации сервера, например `ADMIN_USER_IDS=1,2`, и перезапускает сервер. Несуществующие или некорректные ID не допускаются: сервер откажется запускаться. Прежний `ADMIN_EMAIL` не даёт привилегий.
3. У назначенного пользователя `/api/auth/me` вернёт `admin: true`. Для отзыва удалите ID из настройки и перезапустите сервер.

ID могут использоваться повторно после удаления аккаунта или замены базы. В таких случаях сначала удалите старые ID из настройки и заново проверьте назначения. Ограничьте доступ к конфигурации сервера.

Старую базу `museum.db` версии 2 перенести нельзя: структура изменилась, файл `museum-v3.db` создаётся заново.
